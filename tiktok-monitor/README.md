# TikTok Monitor для Telegram

Личный монитор публичных TikTok-профилей. Работает на хостинге через Telegram long polling. Публичные страницы TikTok бот читает напрямую. Для запуска нужен только токен Telegram-бота.

## Установка на botHost.ru

1. Распакуйте ZIP. Загрузите файлы из него в корень репозитория GitHub, включая main.py, storage.py, tiktok.py и requirements.txt. Можно также загрузить сам ZIP через панель botHost.
2. Создайте Python-бота в botHost, выберите репозиторий и ветку или загрузку архива. Выберите Python 3.11 или новее. Файл запуска — main.py (команда при ручной настройке — `python main.py`). Запускайте один экземпляр.
3. В панели добавьте переменные окружения из таблицы. Файл .env.example служит образцом. Приложение читает окружение процесса.
4. Убедитесь, что для бота доступно постоянное хранилище /app/data. Там SQLite хранит историю, разрешения, подписки и очередь уведомлений. Запустите бота и проверьте журнал.
5. В Telegram откройте своего бота и отправьте /start, затем /add @имя. Через /list видны время последней проверки и ошибки. Нажмите «Статистика» для выбора периода.

| Переменная | Значение |
|---|---|
| BOT_TOKEN | Токен от @BotFather. Хранить в панели хостинга. |
| OWNER_ID | 7325597184 (владелец @lapiduser, значение по умолчанию) |
| DATABASE_PATH | /app/data/monitor.db |

Инструкции хостинга: [ZIP](https://bothost.ru/docs/upload-bot-archive), [GitHub](https://bothost.ru/docs/git-repository-access), [переменные окружения](https://bothost.ru/docs/environment-variables), [хранение базы](https://bothost.ru/docs/database-storage).

## Доступ и команды

Пользователь пишет боту /start и получает свой числовой Telegram ID. Владелец отправляет `/grant 123456789`, после чего пользователь снова отправляет /start. `/revoke 123456789` отзывает доступ и удаляет подписки пользователя. Каждый видит свои подписки и получает свои уведомления. Команды работают в личном чате.

| Действие | Команда |
|---|---|
| Разовая проверка публичного аккаунта | /check @имя |
| Добавить или удалить подписку | /add @имя или /remove @имя |
| Состояние каналов, подписчики, суммарные лайки профиля | /list |
| Запустить проверку ваших каналов | /refresh |
| Последние пять обнаруженных публикаций | /last @имя |
| Прирост всех каналов или одного | /stats 7 или /stats 7 @имя |
| Напомнить подать на выплату через 6 суток после публикации | /pay @имя 6 |
| Отключить напоминания по каналу | /pay @имя 0 |
| Посмотреть ближайшие сроки и ссылки | /due |

По умолчанию напоминание приходит на шестые сутки. Дата считается от публикации. Если срок наступил во время простоя, сообщение придёт после запуска. Уже истёкшие на момент подписки сроки пропускаются. Кнопка «Заявка подана» отмечает конкретный ролик. Настройка меняет сроки ожидающих заявок. Подача заявки в платёжный сервис остаётся за пользователем.

## Как читать отчёты

- Периоды — скользящие 1, 3, 7, 14, 30 и 365 суток. Бот выводит фактические даты начального и конечного замеров для каждого канала. Исходный замер — ближайший доступный на начало периода или первый после подписки. Время отображается в UTC.
- /check и /last показывают просмотры, лайки, комментарии, репосты и сохранения каждого видео. Прочерк означает, что TikTok не вернул показатель. В /last сохранено последнее доступное значение каждого счётчика.
- /stats складывает изменения доступных счётчиков между замерами. Первый замер ранее опубликованного ролика задаёт базу. Для обнаруженной новой публикации, вышедшей после предыдущей проверки, первые доступные счётчики входят в прирост. Уменьшения тоже учитываются. При недоступных счётчиках итог охватывает только измеренные изменения. Ноль может означать отсутствие измеренного изменения. История за год накапливается в течение года.
- Публичная витрина TikTok отдаёт ограниченную подборку (при проверке — 10 роликов). Бот каждый цикл ищет новые ID, проверяет подробные счётчики подборки и до четырёх ранее обнаруженных роликов вне неё по очереди. Последние пять определяются по дате публикации среди обнаруженных. При частых публикациях между опросами часть роликов может не попасть в подборку. Старый необнаруженный архив, удержание аудитории, заработок и данные TikTok Studio публичному чекеру недоступны.
- Цикл стартует каждые 300 секунд при свободном обработчике. Аккаунты проверяются последовательно. Если полный обход дольше пяти минут, следующий начинается после завершения. Ручные запросы на обновление объединяются. Публичные страницы могут кэшироваться, быть закрыты или временно блокироваться для IP хостинга. При ошибке получения профиля /list показывает её и время последнего успеха. При недоступной странице отдельного видео используются доступные публичные просмотры.
- Алерт срабатывает строго при **более 5 000** просмотров. Старый ролик, который уже был выше порога при подписке, не вызывает лавину сообщений. После подписки уведомление приходит при наблюдаемом переходе через порог либо при первом обнаружении нового ролика уже выше порога. Уведомление содержит канал, название, просмотры и ссылку. Для каждого пользователя событие ставится в очередь один раз. Если сервер упадёт после приёма сообщения Telegram, но до записи подтверждения, при восстановлении возможна повторная доставка.
- Когда последний пользователь удаляет канал, бот удаляет его историю. При повторном добавлении накопление начинается заново.
